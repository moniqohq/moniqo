Moniqo is open source, and that's not a technicality — it fundamentally changes how the product is built. The people who use Moniqo every day are also the people who shape what it becomes.

## Where feedback lives

Most product decisions at Moniqo start in GitHub issues. When a user files a bug report or feature request, it enters the same queue that the core team reviews weekly. A well-explained issue — with context, screenshots, and a clear explanation of the problem — routinely makes it into the roadmap.

## Community-driven features in v0.4.0

The improved CSV import started with community reports. Users shared their bank's export formats, and contributors submitted PRs to add native support for each one.

## How to contribute

You don't have to write code. Opening a detailed issue, participating in discussions, or helping another user in the community all move things forward.

If you do want to write code, the `good first issue` label in GitHub is a curated list of tasks that are approachable for first-time contributors. We review PRs quickly and always leave constructive feedback.

The best version of Moniqo is built by the people who use it. We're grateful for everyone who participates.
